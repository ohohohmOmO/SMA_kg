# SMA疾病知识图谱构建与数字孪生底座技术方案 (v1.0)

## 0. 项目概述
本项目旨在构建一个高密度的脊髓性肌萎缩症（SMA）领域知识图谱。该图谱将系统化地整合SMA的致病基因（如SMN1、SMN2）、发病机理、临床表型及药物治疗数据，作为SMA数字孪生系统底层的核心逻辑引擎与数据支撑。

## 1. 阶段一：数据获取与动态平衡 (Data Acquisition & Balancing)
**技术目标：** 解决研究领域文献分布不均的问题，确保致病机理、表型特征、治疗方案等维度的知识密度均衡。

**技术细节与工具：**
* **骨架锚定：** 使用 Python `requests` 库调用开源医学数据库 API（DisGeNET, Orphanet, HPO），直接获取高度结构化的核心基因-表型关联数据。
* **广度文献爬取：** 编写定向爬虫（结合 `BeautifulSoup` 或 `Scrapy`）对接 PubMed/Web of Science，使用“Spinal Muscular Atrophy”等基础关键词，获取首批 5000 篇文献的摘要及元数据（标题、作者、发表时间）。
* **无监督主题聚类：** 引入 `BERTopic` 模型，将首批文献自动聚类为“致病机理”、“新筛与诊断”、“药物干预”等主题簇。
* **特征词提取与二次检索：** 统计各簇密度。利用 TF-IDF 提取稀缺主题簇（如底层基因机制）的核心特征词，自动生成高级检索式返回 PubMed 补充爬取，直至数据大盘达到预设的平衡比例。

**执行规则：**
1. 爬虫必须设置合理的请求延时（Time.sleep），遵守目标网站 robots.txt 协议。
2. 原始文献数据以 JSONL 或 CSV 格式统一存入本地 `data/raw/` 目录。

## 2. 阶段二：混合双擎知识抽取 (Knowledge Extraction)
**技术目标：** 在零人工标注的条件下，高精度、大规模地从非结构化文本中抽取实体（Entity）与关系（Relation）三元组。

**技术细节与工具：**
* **LLM 弱监督标注：** 编写高质量 Few-shot Prompt，调用大语言模型（如兼容的 OpenAI API 或国内主流大模型 API）随机处理 500 篇已清洗文献，提取标准三元组（如 `(SMN2基因, 表达, SMN蛋白)`），生成“银标准”训练集。
* **小模型蒸馏与微调：** 部署本地开源预训练模型（推荐 `UIE-med` 或针对医疗领域的 `BioBERT`），利用 LLM 生成的 500 篇数据进行 LoRA/P-Tuning 微调。
* **全量推理：** 使用微调后的本地小模型高效处理剩余的数万篇文献，完成全量知识抽取。

**执行规则：**
1. 抽取的实体需严格限制在预设的类别内（如：Gene, Disease, Phenotype, Drug, Pathway）。
2. 抽取结果需包含置信度得分（Confidence Score），低于阈值（如 0.85）的数据需进行二次校验。

## 3. 阶段三：多维知识融合与对齐 (Knowledge Fusion)
**技术目标：** 消除多源数据的冗余、歧义与冲突，确保知识体系的唯一性与客观性。

**技术细节与工具：**
* **实体映射与消歧：**
  * 建立本地同义词词典（如“SMA”、“脊髓性肌萎缩症”、“Spinal Muscular Atrophy”全部映射至统一 ID）。
  * 引入 `SciBERT` 生成未登录词的词向量，计算余弦相似度，对相似度 > 0.9 的近义医学名词进行合并。
* **冲突仲裁机制：** 针对互相矛盾的关系边，引入权重计算模型。计算公式融合：数据源权威性（数据库API > 顶刊 > 普通文献） + 算法抽取置信度 + 共现频率，保留高权重边。

**执行规则：**
1. 所有融合操作必须保留溯源字段（Source_Trace），记录每一条关系来自于哪篇文献的哪个段落。
2. 融合后的高质量三元组统一保存至 `data/processed/` 目录。

## 4. 阶段四：图谱存储、计算与可视化 (Storage, Computation & Visualization)
**技术目标：** 实现图数据的持久化存储，支持复杂网络计算与前端交互展示。

**技术细节与工具：**
* **混合持久化：**
  * 使用 **Neo4j** 图数据库作为核心，利用 Cypher 语言构建节点（Node）和关系（Edge）。
  * 将文献的原始文本存入结构化文件，与 Neo4j 节点通过 ID 关联。
* **图数据科学 (GDS) 分析：** 利用 Neo4j 内置算法，运行 PageRank 计算核心致病枢纽基因，运行社区发现算法（Community Detection）探索潜在的发病机制模块。
* **动态可视化：** 基于 **ECharts** 或 **AntV G6** 构建本地 Web 页面，实现节点搜索、关系过滤、多跳路径高亮等交互功能。

**执行规则：**
1. 写入 Neo4j 前必须建立索引（Index），特别是对核心实体 ID 进行约束，防止重复创建节点。
2. 可视化界面需提供良好的响应式体验，节点颜色与大小需直观反映其类别与图论中心度。
