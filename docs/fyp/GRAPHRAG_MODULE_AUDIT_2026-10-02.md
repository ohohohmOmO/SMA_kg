## 沿用与改进

沿用原手绘：问题 → 文本/图检索 → 原文证据上下文 → 带引用的结构化声明 → 引用完整性 → 声明支持判断 → 回答/部分回答/拒答。

1. 图谱用于寻找证据，不能当作已验证事实库。沿用新版类型/来源/版本键，保留SMN1/SMN2及Gene/Protein差异；旧 `Entity` 名称查询不能直接复用。现有原型已接入新版，不需要再次重建图谱。
2. 冻结输入哈希和活动版本；图谱更新后重建相应索引、邻域/路径缓存及图证据ID，并重跑问答和校验。原PMID/原文记录在内容不变时可复用；旧生成答案的检查结果不能自动继承。
3. 回答必须回到原文。保留证据ID与PMID、引用句子及偏移，分开判断引用完整性和内容支持。Open Targets关联、多跳路径、融合置信度都不能直接证明因果或疗效。
4. 采用生成原子声明的方式避免先生成无约束长回答；核对实际展示文本是否保留物种、人群、亚型、时间、剂量、方向、数值、否定和不确定性。模型失败或证据不足时保守处理。
5. 单独评价检索、引用和声明支持。原400条抽取标签可复用其错误类型设计挑战题，不能自动成为QA答案或新声明的金标准；新任务需要独立人工评价，并避免把开发案例当独立测试。

## 建议完成顺序

先将现有草稿整理为可复现的小规模闭环：冻结图谱/原文 → CLI或简洁展示入口 → 专项回归 → 少量真实问答及完整请求/响应记录 → 固定评价集与人工答案/声明标签 → 控制变量对照 → 状态文档和报告同步。

可先准备30–50个固定研究问题作为规模建议，不是学校硬性数量。覆盖机制、治疗研究、SMN1/SMN2区分、类型差异、物种/亚型范围、冲突和证据不足。冻结方法后再使用独立测试题评价。

离线对照可包括文本RAG、图RAG、图RAG加引用检查、图RAG加引用和声明检查；统一语料、模型、问题和预算。在实验记录中评价未校验草稿，正式回答仍只展示通过检查的声明。报告检索证据覆盖、引用错误、人工严格支持、误接受、正确声明被过滤、回答/拒答比例、延迟和真实费用。

当前实现是有界局部图检索加文本检索的原型，没有证据证明完成社区摘要或全局GraphRAG；原手绘的局部流程并不要求同时增加这些模块。是否承诺全部三个模块应与项目范围一致，但完成检查不等于本次已实施这些后续工作。
