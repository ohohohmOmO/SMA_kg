# SMA 毕设人工审核与验证操作指南

日期：2026-10-02。本文用于开始当前毕设质量评价。审核结论必须由实际评审填写；示例为教学用假设，不是现有候选的金标准标签。

## 现在开始做什么

1. 阅读现有 `outputs/fyp_gold_annotation_2026-10-01/SMA人工标注集_400条.xlsx` 的“说明与进度”页。保留原始候选记录，在 Excel 中另存一份工作副本并定期备份。
2. 先使用现有 400 条之外的 10—20 条试审核样本或本文的假设示例统一规则。与导师讨论哪些关系允许推断、疾病亚型和实验条件如何处理。不能在 300 条随机主集上反复调整阈值。
3. 确定第二评审的时间。主审由学生完成，预先标记的 80 条由另一位能够理解材料的人员独立复核；不需要第二人重做全部 400 条。
4. 正式审核从 `candidate_id` 逐条进行，建议每天 10—15 条。每次记录真实时间、难点和决定；不会的条目先记 U 和原因，不要为了凑进度猜测。
5. 同期完成图谱证据界面、证据定位、融合审查和系统任务验证。学生主要提供人工标签、裁决和操作反馈，程序负责结构、来源、进度和统计检查。

当前基线审核使用保存的标题与摘要。若查看 PubMed 网页确认来源，记录访问情况；若网页内容与快照不同，先记录版本问题。全文或外部知识可以帮助理解术语，但不能拿摘要之外的事实补成“摘要直接支持”。

## 一条候选怎样审核

### 第一步 先读摘要

查看 E 列 title 和 F 列 abstract，辨认研究对象、研究设计、关键结果、否定词与限定条件。记录证据来自患者、小鼠、细胞、特定疾病亚型、变异、缺失或某个治疗阶段等。初次判断时隐藏 M—O 列的自动匹配、计算评分和模型名称；必要时也隐藏 B—C 的分组/复审标记，减少锚定。

### 第二步 把三元组读成一句话

G/H 是实体 1 与类型，I 是关系，J/K 是实体 2 与类型。问：摘要是否表达了“实体 1 通过关系 I 联系实体 2”？两个名称都出现并不意味着该关系成立。

尤其检查：

- 关联是否被夸大为因果；假设或可能性是否被改成确定事实。
- 基因的缺失、变异、低表达是否被压缩成正常基因本身的作用。
- 小鼠、细胞或特定患者亚组的结果是否被当成不限条件的结果。
- 否定、无显著效果、比较组或治疗前后方向是否被误读。
- Gene/Protein、Disease/Phenotype、Variant 等类型是否对应正确。
- 非典型 SMA 疾病、亚型和相关疾病是否被混为同一种疾病。

对于有方向关系，箭头必须与原文一致。ASSOCIATED_WITH、CO_OCCURS_WITH 等通常具有对称语义的关系，按预先约定的表示规则判断方向，不因为纯粹交换两端就判定科学关系错误。判断规则在正式审核前固定。

### 第三步 分别判断整篇支持和证据片段

Q 的 support_label 回答“保存的标题/摘要是否支持这个候选关系”。V 的 evidence_span_correct 回答“模型给出的 L 列证据片段是否可追溯、足以支持关系及其限定”。两者不是同一个指标。

例如，整篇摘要明确给出某项结果，但 L 只写了一个结局名称：Q 可以是 2，而 V 可以是 no。M=yes 只是自动字面匹配，不说明该片段包含完整关系。M=no 也可能源于大小写、空格、省略、改写或跨句，不能据此直接把 Q 判为 0。

V 的操作规则：

- yes：片段可定位到来源，且包含足够的关系和关键上下文；多个片段必须能分别定位且共同支持该关系。
- no：片段编造、遗漏关系主体/谓词、丢失关键否定或条件，或者无法作为提供的证据追溯。
- unclear：来源或语义需要进一步裁决。

有省略号、改写或跨句证据时，在 AA 说明来源位置并复制足够的完整原句；不要修改原始 L 列来掩盖抽取问题。正文关系可被支持而证据片段不合格。

### 第四步 填写主审列

| 列 | 字段 | 操作 |
| --- | --- | --- |
| A—O | 候选和自动诊断输入 | 保留原始值，不改 ID、PMID、分组、三元组、证据或评分；排序须排序整张表 |
| Q | support_label | 2 直接支持；1 部分/隐含支持；0 不支持或矛盾；U 暂时无法判断 |
| R、S | 两个实体是否正确 | 分别核对名称指代和 H/K 类型，填 yes/no/unclear；类型错误在 W 和 AA 中说明 |
| T | relation_correct | 是否确实表达该关系，填 yes/no/unclear |
| U | direction_correct | 是否符合原文与预先约定的方向规则 |
| V | evidence_span_correct | 片段是否可定位且足以作为关系证据 |
| W | error_type | 选择主要错误；无错误填 no_error；多个错误在 AA 补充 |
| X | corrected_triple | 可可靠修正时写 `Entity 1 | RELATION | Entity 2`，无需强行修正 |
| Y、Z | reviewer_id、review_date | 实际评审代号和真实审核日期 |
| AA | review_notes | 写判定理由、原文句子、限定条件、次要错误；Q 非 2 或 V 非 yes 时必须说明 |
| P | review_status | 未审 pending_review；主审完成 completed；需裁决 needs_adjudication；不要直接 excluded 删除难例 |

现有表没有独立的“实体类型正确”列，因此 R/S 同时包含名称和类型判断；不能声称从现有列直接算出了独立的类型准确率。如需单独类型指标，先明确新增字段方案，不修改已经审核过的含义。

2 要求整篇摘要直接支持实体、关系、方向和关键条件，R/S/T/U 应为 yes。1 用于有支持但过度概括、缺少关键条件或需要推断，不能把任意共现都算成部分正确。0 用于完整可读摘要没有提出该关系、关系或方向错误、否定被忽略等。U 用于来源/语义确实无法裁决，不是所有低置信度样本的默认标签。

若 U 需要进一步裁决，P 先写 needs_adjudication。裁决后仍无法判断也可以保留 U，记录原因和裁决者/日期，之后统计时明确展示这部分样本；不能悄悄丢弃。

### 教学用假设示例

以下为虚构文本，禁止当作真实 SMA 文献结论或金标准数据。

| 假设来源文本 | 候选 | 判定思路 |
| --- | --- | --- |
| In the studied patients, treatment A reduced symptom B. | A — DECREASES → B，证据为完整原句 | 可判 2；实体/方向正确且条件保留时各项 yes |
| We compared treatment A and treatment C. Symptom B was measured. | A — TREATS → B | 两者出现，但没有治疗效果或所称关系证据，判 0 |
| Treatment A did not improve symptom B. | A — IMPROVES → B | 片段字面真实但关系忽略否定：Q=0、T=no；W=negation_error |
| Treatment A may improve symptom B in a mouse model. | A — TREATS → Disease D，无条件限定 | 不能判 2；按“部分支持还是无所称关系”裁决为 1 或 0，写出推断和条件丢失 |
| 来源不可读或术语含义暂不能确定 | 任意候选 | 先 U，写明缺失信息并请求裁决 |

## 第二评审与裁决

1. 根据 C=yes 选出原先指定的 80 条。给第二评审独立副本，只展示 ID、PMID、标题、摘要、实体/类型、关系和证据，不展示主审 Q、笔记、模型评分或最终裁决。
2. 第二评审填写 AB=second_reviewer_id、AC=second_support_label、AD=second_review_date、AE=second_review_notes。若在独立副本上工作，合并时按 candidate_id 对齐，不能按排序后的行号粘贴。
3. 原始主审 Q 和第二评审 AC 均保留。标签不一致时讨论原文并填写 AF=adjudicated_label、AG=adjudication_notes，AG 包含原因、参与者与实际日期。
4. 一致性使用裁决前的 Q 与 AC；最终质量使用裁决后的 AF（没有裁决时使用 Q）。对非预定 80 条的额外专家审核，单独说明，不混入预定一致性样本。

主审完成数、第二评审完成数和最终可统计数是不同的进度。已有“说明与进度”页的 completed 计数只反映状态字段，不能自动证明标签、日期、独立复审和裁决完整。

## 完成后怎样统计

新增脚本 `src/evaluation/summarize_gold_review.py` 只读工作簿、不调用 API、不生成任何人工标签。它检查样本身份和保护字段、必要主审字段、不同第二评审、分歧裁决，分别输出主集/挑战集进度。

在 `KG_SMA_env` 下运行，输出文件名每次使用新日期/批次，脚本拒绝覆盖已有报告：

```powershell
& 'C:\Users\jon15\anaconda3\envs\KG_SMA_env\python.exe' src/evaluation/summarize_gold_review.py --workbook 'outputs/fyp_gold_annotation_2026-10-01/SMA人工标注集_400条.xlsx' --output 'artifacts/runs/fyp_readiness_audit_2026-10-02/human_review_progress_next.json'
```

若在工作副本审核，用 `--workbook` 指向该副本。第一次生成以后改用新文件名。未完成的组仅报告进度，不把空白当成 0 分，也不输出总体质量估计。

- 300 条 primary_random 是主指标样本；100 条 challenge 用于单独困难案例与错误分析，不能混算总体准确率。
- 主严格支持率：2 标签数 / 已裁决且标签为 0、1、2 的主样本数。宽松支持率把 1、2 都计入，但“部分支持”不能被描述为完全正确。
- U 数量和占比必须同时报告。脚本也给出全部样本中的确定支持比例，以及 U 全部判错/全部判对时的范围，防止只排除 U 后得到看似很高的结果。
- Wilson 区间是近似独立预测假设下的区间；多个样本共享 PMID 时应说明相关性，必要时补充按 PMID 聚类的不确定性分析。
- Cohen's kappa 使用预定双评样本的原始分类；一类标签占全部样本时 kappa 可能无法定义，此时报告一致率与分布，不强行填 1。
- 这套评价衡量 Stage 2 预测的摘要支持度，不能直接充当融合边质量、GraphRAG 答案正确率或召回率。Recall/F1 需要额外完整摘要穷尽标注与明确定义的匹配规则。

历史 `metrics_calculator.py` 使用另一套 CSV 与人机比较口径，且缺 API key 时存在固定分值回退。它不用于本次 400 条人工质量结果。自动评价与人工评价不能互相冒充。

Neo4j 验证先明确管理数据范围，采用只读查询；不为了查数重新运行默认会清空托管图谱的 Stage 4 导入。数据库中的文献与外部关联口径不同，计数不能直接机械相加。

融合审核建议先另取约 50 个变更映射作为试审，并增加容易误合并的挑战案例。它们是另一套评价单元，不混入 Stage 2 的 400 条支持率。对比相似名称时应查看原文和实体语境，不能因 embedding 很近就确认同一实体。

证据定位算法开发使用独立开发样本；用固定审核样本评价时，记录阈值、配置及规则。比较改进前后正确率的同时报告保留率，不通过删除难例来制造提升。
